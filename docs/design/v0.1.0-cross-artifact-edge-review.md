# Sothoth v0.1.0 Cross-Artifact Edge and Closure Review

Status: non-authoritative review record, pending human acceptance review

Review identity: `SOTHOTH-CROSS-ARTIFACT-EDGE-REVIEW-0.1` revision `1`

Target release: `0.1.0`

This document is the closed cross-artifact edge review required by the pre-design boundary before
any formal Scope BOM may exist. It reviews all eleven proposed Dossiers, their registrations, and
the contract edges between them, in both directions, and records the resulting closed package
dependency DAG with its deterministic waves. It is a review record only.

## Review identity and boundary

- This file is not a Dossier, is not bound to `sothoth.design-dossier/full/v1`, and does not appear
  in the document registry or in the artifact design registrations.
- It defines no public schema and no contract: the machine record below deliberately carries
  neither a `schema` nor a `kind` identity, only a local review identity.
- It has no acceptance effect: no Dossier, registration, or baseline changes status because this
  review exists, and no verdict below expresses human acceptance — every verdict expresses a
  compatibility check between declared Source Facts.
- It neither generates nor implies an Architecture Baseline or a Scope BOM.
- It binds the exact Source Facts it reviewed through the closure projection digest
  `sha256:7b773f641a59516b4972bede709a1b10aa4b79f6c3c42a496ad3da9673178ada`, which is the
  `sourceFactsDigest` of the `sothoth.design-closure-projection/v1` compiled from the same facts by
  `scripts/check-pre-design.mjs --phase closure`.

<!-- sothoth:review-section id="derivation-method" -->

## Derivation method

- A Producer/Consumer contract edge is the exact match of three things: one provider component's
  `providedContractRefs`, one consumer component's `requiredContractRefs`, and one complete
  contract identity with revision. Edge direction is always `provider -> consumer`.
- The eleven registrations derive exactly 33 contract-edge instances. Distinct contract refs on the
  same package pair remain distinct edges: `@sothoth/governance -> @sothoth/sdk` carries three
  separate edges (`CHANGE-PLAN@1`, `GOVERNANCE-COMPILATION@1`, `PRE-DESIGN@1`) and is never merged
  at the contract level. Every required contract resolves to exactly one provider.
- Collapsing the 33 edges by identical provider/consumer pair yields 31 unique package dependency
  edges, with no self edge, no reverse pair, and no cycle.
- Waves are zero-based: a package enters the first wave in which every contract-dependency
  predecessor is already placed, and members within a wave are ordered by Unicode code point. The
  derivation terminates with all eleven packages placed, which is the acyclicity proof.
- Package order here comes only from exact contract dependency. No `impact`, `validation`,
  `history`, or `navigation` relation is promoted to an ordering edge.
- All canonical orderings in this review (component reviews, edge rows, package edges, wave
  members, contract refs, section refs) use Unicode code-point order.
- Stable edge identity is `providerComponentId -> contractRef -> consumerComponentId`, joined with
  the literal `->` separator; no component id or contract ref contains that separator.

## Component review summaries

Every edge is reviewed in both directions: for each `provider -> consumer` edge the provider side
must declare `provides` and the consumer side must declare `requires`, and each side must resolve
to that component's review record below. Each of the eleven component reviews cites exactly five
stable Dossier sections — `authority-security-and-effects`,
`deployment-configuration-and-operations`, `failure-recovery-and-consistency`,
`observation-and-audit`, and `state-lifecycle-and-data-flow` — by
`documentId + documentRevision + sectionId`.

- `@sothoth/cli` — CLI executable package (`cli-executable-package`); operator-facing composition
  and I/O adapter; compatible.
- `@sothoth/contracts` — declarative type-and-schema library (`pure-library-package`); inert,
  zero-runtime-dependency owner of the closed vocabulary; compatible.
- `@sothoth/core` — pure-function compilation kernel (`pure-library-package`); canonicalization,
  digesting, diagnostic and outcome aggregation; compatible.
- `@sothoth/document-index` — structural document indexing library (`pure-library-package`);
  CommonMark AST to deterministic index projection; compatible.
- `@sothoth/git` — read-only Git source adapter (`library-adapter-with-git-child-process`);
  five allowlisted read-only subcommands, never mutates a repository; compatible.
- `@sothoth/governance` — document-governance domain compiler (`pure-library-package`);
  registry, ledger, closure, admissibility, and change-plan compilation; compatible.
- `@sothoth/graph` — generic graph algorithm library (`pure-library-package`); meaning-free
  traversal, SCC, condensation, waves, longest paths; compatible.
- `@sothoth/planning` — scheduling domain compiler (`pure-library-package`); dependency
  validation and deterministic wave assignment only; compatible.
- `@sothoth/profile-sdk` — consumer-neutral contract, loading, and conformance library
  (`pure-library-package`); compatible.
- `@sothoth/sdk` — aggregate public library facade (`pure-library-package`); delegation-only
  typed-outcome envelope, sole facade, never selects exit codes; compatible.
- `@sothoth/selectors` — declarative selector engine (`pure-library-package`); closed query
  algebra over document-index entries; compatible.

No component is described as a daemon, a service, or an independently probeable health-check
endpoint: every component besides the CLI executable and the Git adapter is a library, and both
adapters stay inside their Dossier fences.

## Package dependency DAG and deterministic waves

Collapsing the 33 contract edges by identical provider/consumer pair gives 31 unique package
dependency edges — `@sothoth/governance -> @sothoth/sdk` collapses its three contract edges into
one pair while every other pair carries exactly one contract ref. The DAG has no self edge, no
reverse pair, and no cycle: the wave derivation places all eleven packages in eight zero-based
waves, `@sothoth/contracts` alone in wave 0 through `@sothoth/cli` alone in wave 7. The full
31-edge list and the eight waves are recorded in the machine review record below; within-wave
members and every array in this review are ordered by Unicode code point.
